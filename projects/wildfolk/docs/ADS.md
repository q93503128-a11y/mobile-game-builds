# Rewarded Ads · Foundation3

Exactly two logical placements: `rewarded_gem` and `rewarded_revive`. Provider Google AdMob Unity11.6.0 (official release2026-10-13), native Android Standard25.5.0 + UMP4.0.0. Official package license/metadata retained. Existing EDM1.2.182 is reused; the GMA editor's automatic EDM2 installation is disabled to avoid two resolvers. iOS/native mediation/banner/interstitial/IAP are outside this pass.

## Policy and authority

Server `backend/src/ads-config.json`: 1Gem/completed verified claim, 1Gem/server UTC day, 0second cooldown. Starting0, lifetime achievement213, newcomer45, monthly40, Engineer120 and Gem revive8 remain unchanged. At1/3/5/10 ads per day uncapped30-day supply is30/90/150/300; the adopted cap supplies at most30 in30days and90 in90days. No-ads example: newcomer45 + two fully completed monthly boards80 =125, enough for Engineer without ads or achievements. This is an explicit activity assumption, not observed retention/revenue. See [model](../validation/rewarded-ads-meta-ui/ad-economy-model.json).

Recoverable Google-linked account and current online server eligibility are required BEFORE a Gem ad. Device clocks/reported amounts/SDK bools never mint Gem. The server reserves one canonical player/environment/UTC-day slot, fixes amount/unit/day/nonce and leases it to one device for10minutes. Failed/no-fill/cancel shows can retry that same slot without consuming the claim. A late earned receipt belongs to its reserved day. No fake cooldown or ad-available badge is shown.

`IRewardedAdProvider` separates Google SDK from runtime/economy. Native adapter accepts only the SDK reward-earned callback; close, start, store-open, impression and elapsed time are not success. Native fullscreen state is exclusive, repeated/late callbacks are ignored, and disposing a provider completes its outstanding show as failure. Android platform, reviewed audience/privacy configuration and UMP Update → consent form if needed → CanRequestAds precede initialization/load. Privacy choices entry appears only when the native UMP status requires it. Missing/legal-unspecified configuration is unavailable. No Editor placeholder ad counts as a real ad.

## Gem verification and durable processing

Client persists account/environment-scoped operation before show and attaches UGS player ID plus `lf3.environment.operation.nonce.rewarded_gem` as Google SSV custom data. Client earned notification only marks pending. Its checksum/atomic-replace/backup journal keeps delayed days in a bounded retry queue; only server responses update the wallet view. UI open/manual retry and a bounded post-completion check perform reconciliation, not per-frame HTTP. Account changes invalidate pending async responses; local deletion clears the selected account journal.

Google GET callback → public Cloud Run `/admob/ssv` → fixed Google keyserver P-256 ECDSA verification of the ORIGINAL encoded query → durable CloudTask →200 acknowledgement. Google retries only five times at one-second intervals, so acknowledging before durable enqueue is forbidden. The private task retains signed query/public verification key/received-at for seven days, sealed with server HMAC. Worker `/deliver` verifies Google OIDC issuer/audience/exact worker account, HMAC/scope/age, then the retained ECDSA key. It exchanges a server-side UGS service-account credential for a token and invokes `LowfireRewarded.ReceiveAdMobSsv`.

Cloud Code independently verifies the relay HMAC, project/environment/channel and provider timestamp, then matches the server operation nonce/unit/amount/placement/player. It saves a verified receipt intent BEFORE binding the permanent global provider receipt owner. The existing Economy2 CAS ledger writes `Reason=rewarded_ad`, source `ad:admob:SHA256(provider transaction)`, placement/operation/receipt/day/transaction metadata. Archived source indexes and global owner binding prevent replay after compaction or changing devices/accounts. Unknown CAS responses retry the same receipt. Server pending intent survives client loss. Stopping new shows does not discard already verified reserved rewards. The relay secret is never in Unity, Cloud Save or Git.

Authenticated suspicious requests are bounded to32 evidence entries/day and mark Suspicious, never automatic ban. Unauthenticated forged callbacks are rejected/logged in aggregate without allowing an attacker to mark an arbitrary victim account. Legitimate duplicate delivery is an idempotent success, not automatic abuse. Support: `node backend/tools/admin.cjs ads-lookup --project ... --environment ... --player ...`; this summarizes day/amount/operation/placement/state/receipt/transaction and bounded client revive diagnostics, with nonce/raw proof omitted. Existing economy history/source/reconciliation/adjustment tools remain authoritative; adjustments still require operator/case/reason. Account deletion marks each environment under the same short creation gate used for new receipt binds. Workers recheck the account inside that gate, so a deletion arriving while a bind waits cannot leave a new orphan receipt. A known read-only rejection releases the gate; ambiguous storage failures retain the existing operator recovery rule. Cleanup then enumerates hot ledger, archives and verified pending intents, deletes owner-checked global financial bindings before their manifests, then existing archive/index/player/Auth cleanup. Retry resumes after partial deletion.

## SP revive

Official SDK earned completion can support guest SP revive; this is local SP authority, not a server-verified Gem receipt. Modified clients are outside that local trust boundary. The proof is bound to `Run:death:ad`, saved before callback, and retained until the WORLD save commits. Failed/cancelled/no-fill earns nothing. A failed world write leaves Dead/AdUsed=false and retains the earned proof for safe retry/reload without a second ad. Success uses existing nearest safe death position,40%HP and existing protection, once per expedition. Home starts a new expedition; old callbacks/proofs cannot revive a different run/death. Free Home and Gem8 remain separate; LAN offers neither paid nor ad field revive. Connected revive support reports are explicitly `client_reported_not_financial`, deduplicated and cannot grant currency.

## Build channels and remaining external activation

Committed defaults: client Enabled=false, PrivacyReviewed=false, Audience=Unspecified, ProductionLiveEnabled=false, real units empty; private Development/Alpha server Enabled/SsvReady/ProductionLiveEnabled=false. Production service policy was not changed. The Development provider requires explicit isolated QA injection and is absent from Alpha/Production compiled runtime. Non-production SDK defaults to Google's official sample rewarded unit. Two logical placements may share that sample ONLY during sample testing. An explicit `UseRegisteredTestUnits` path supports the app's own two rewarded units on registered test devices: reviewed settings, two valid distinct owned IDs and a bounded test-device list are required; native `AdRequest.isTestDevice(Context)` must return true immediately before BOTH load and show, otherwise no ad request/show is allowed. Production never uses this test path or its test-device list. Production requires two distinct real rewarded units, reviewed consent and explicit client/server/ingress live activation, plus real AdMob app ID. No fallback grants or real-money purchases exist.

Official sample units demonstrate SDK test video callbacks but cannot be assumed to send SSV to this app's own endpoint. AdMob's SSV testing tool verifies the SERVER path separately. For the eventual owned-unit Alpha end-to-end test, set `UseRegisteredTestUnits=true`, actual owned Gem/Revive unit IDs and the device IDs officially registered in AdMob/RequestConfiguration; the native SDK independently verifies that the CURRENT device is actually in test mode before load/show. This is fail-closed if the public API is unavailable or returns false. The public method was verified directly with javap against Google's pinned play-services-ads-api25.5.0 AAR ([public API evidence](../validation/rewarded-ads-meta-ui/completion/native-adrequest-api.txt)); no guessed/private SDK method or client-supplied `verified` bool is used. No real unit/device ID was filled in, and no real video/SSV/device test has run. Keep all activation flags OFF until setup and actual Test Ad/SSV/consent verification.

SDK/UMP callbacks dispatch explicitly through the pinned MobileAdsEventExecutor. Initialization and loads time out after20seconds without granting rewards; expired/duplicate/late completions are ignored. A closed ad is not an earned ad. Fresh eligibility lookup failure clears the previous eligible UI state, and malformed account/environment/quota/server-clock replies are rejected.

### Exact setup procedure (no made-up values)

1. [AdMob](https://admob.google.com/) → Apps → Add app → Android → Lowfire, package `com.gltam.lowfire`, select actual Play listing status. Save actual public App ID into `Assets/GoogleMobileAds/Resources/GoogleMobileAdsSettings.asset` with the official Google Mobile Ads Settings editor. Current value is Google's sample app ID, not this game's assigned ID. Do not invent a publisher ID.
2. Apps → Lowfire → Ad units → Add ad unit → **Rewarded** twice, names `rewarded_gem` and `rewarded_revive`. Gem reward amount1/type `lowfire_gem`; revive local action grants no Gem. Retain the two actual public unit IDs for the production settings. No rewarded interstitial, banner or automatic show.
3. AdMob Privacy & messaging → configure the applicable consent messages after audience/child/under-age/privacy review. Publish actual Privacy Policy/Account Deletion URLs through the existing backend settings. Decide General/Child and UnderAgeOfConsent accurately; do not set reviewed=true merely to remove a warning. Validate UMP in relevant regions, denied/required/error paths and privacy-options re-entry. [Official UMP flow](https://developers.google.com/admob/unity/privacy).
4. For the first video smoke test keep the default Alpha/sample units. Confirm the displayed **Test Ad** label; never click live ads. For owned-unit end-to-end testing, register the actual device in AdMob Settings → Test devices following Google's [test-device configuration](https://developers.google.com/admob/unity/test-ads), then put the actual public device hash(es) in TestDeviceIds, real two unit IDs in GemAdUnit/ReviveAdUnit and UseRegisteredTestUnits=true in the isolated QA build's RewardedAdsSettings. Use the actual owned App ID. Test hashes are not server secrets, but keep device-specific QA values out of public evidence. The code checks the SDK current-device test status before load AND show. A misconfigured/unregistered device gets no owned-unit ad. ProductionLiveEnabled remains false.
5. In the user's actual Google Cloud project enable Cloud Run, Cloud Tasks, Secret Manager and container build/registry APIs; choose actual region. Create separate runtime and worker service accounts and a dedicated queue. Runtime: Cloud Tasks Enqueuer scoped to queue, Secret Accessor scoped to the two required server credentials, Service Account User on the worker identity as required for task OIDC. Preserve the Cloud Tasks service agent's documented token-generation permissions. Worker target identity/audience must match exactly. [Official HTTP-task authorization](https://docs.cloud.google.com/tasks/docs/creating-http-target-tasks).
6. Build from projects/wildfolk: `docker build -f backend/ingress/Dockerfile backend`. Deploy to Cloud Run using the runtime service account. Public access is needed ONLY for Google GET SSV; `/deliver` ALSO checks OIDC in application code even when the service is public. Set actual returned HTTPS service URL as `ADS_SERVICE_URL`; no example URL is committed. Set queue max concurrency4, max dispatch rate4/s, max attempts unlimited with max retry duration604800seconds, min backoff10s/max3600s. Verify these settings on the actual queue and alert on oldest task/retry failures before enabling ads.
7. Runtime non-secret environment fields: UGS_PROJECT_ID, UGS_ENVIRONMENT_ID, LOWFIRE_CHANNEL, GOOGLE_CLOUD_PROJECT, CLOUD_TASKS_LOCATION, CLOUD_TASKS_QUEUE, WORKER_SERVICE_ACCOUNT, ADS_SERVICE_URL, AD_MOB_GEM_UNIT_SUFFIX. Values come from the selected real project/environment/service/queue/ad unit; development and alpha need isolated queues/configuration. Production additionally requires `PRODUCTION_ADS_LIVE_ENABLED=true`, which remains absent now.
8. User creates a dedicated least-privilege UGS server service account with Cloud Code execution scope in the actual project. Store key ID and secret in **Google Secret Manager**, bind to runtime as UGS_SERVICE_ACCOUNT_KEY_ID/UGS_SERVICE_ACCOUNT_SECRET; never Unity Resources, repository, command history or chat. Generate a strong random base64url relay key locally; store the same value in GCP Secret Manager as ADS_INGRESS_HMAC and in the selected UGS environment Secret Manager as **LOWFIRE_ADS_INGRESS_HMAC_V1**. Apply role scope in Dashboard and verify token-exchange/Cloud Code rights, not project-wide administrator. Rotation must retain pending seven-day tasks or drain them first; do not revoke a queued reward's only verification key.
9. BEFORE enabling callback traffic, exclude/redact Cloud Run HTTP request logs containing `/admob/ssv` query strings. Those queries include user ID/custom data/signature; application safe-code logging alone does not redact infrastructure logs. Restrict task payload access/retention to seven-day recovery; configure operational retention/deletion and alert delivery. Do not paste raw signed queries or credentials into support/Git.
10. AdMob Lowfire → rewarded_gem → Advanced settings → Server-side verification → actual callback URL **returned service URL + `/admob/ssv`**. Use Google's verification/test tool with an isolated QA UGS player, matching reserved operation/nonce and amount/type; wrong ID/amount/unit must fail. Validate Google key rotation, duplicate/late delivery, durable queue outage, unknown wallet response, task retry and support transaction. A callback without a valid reserved QA operation is correctly rejected.
11. Populate a reviewed ads config JSON (non-secret) with actual Gem unit numeric suffix. `node backend/tools/admin.cjs ads-setup --project <actual project> --environment <actual environment> --config <reviewed file>` is dry-run; `--apply` performs CAS update. Keep Enabled/SsvReady false until ingress and official test-tool verification are complete. Deployment uses canonical `backend/tools/bundle.cjs` and LowfireRewarded only. Do not replace existing policy/gate/economy data. ProductionLiveEnabled=true additionally requires explicit `--confirm ENABLE_PRODUCTION_REWARDED_ADS`; this is a later user-authorized launch action.
12. Before ANY production live activation: actual Android SDK/test video/consent + native Gradle/dependency/device build, owned-unit native test-device guard and actual end-to-end test, real Google-linked account/Play Integrity, SSV/queue/UGS settlement and audit, cross-device/archive/deletion recovery, privacy URLs, monitoring and no-ads progression all pass. Only then activate reviewed client/server/ingress Production flags and real IDs together. Turning them off must still settle verified earned reservations. No activation was performed in this pass.
