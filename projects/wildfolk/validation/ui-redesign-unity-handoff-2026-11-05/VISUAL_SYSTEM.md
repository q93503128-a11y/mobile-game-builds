# 통합 시각 시스템 — 후보 규칙

상태: 파일럿 평가 전 제안. 아래 수치는 구현 확정값이 아니라 출발점입니다. Stage 1.5 토큰은 참고하되 최종 승인을 대신하지 않습니다.

## 시각 성격

Lowfire의 숲·야영·제작 감각을 유지하는 **차분한 survival utility**. 배경 게임 아트가 주인공이고 UI는 행동과 상태를 분명히 합니다. 웹 대시보드 카드 그리드, 장식 테두리, 큰 종이 패널의 반복을 피합니다. 햇빛/불빛색은 중요한 선택과 위험 상태에만 사용합니다.

## 표면 계층

1. **World overlay:** 게임 월드가 계속 보이는 HUD 레이어. 고정/부유 컨트롤은 실제 hit area를 표시하고, 전투 시 장면 가림 비율을 재검토합니다.
2. **Utility surface:** 인벤토리·제작·설정에 쓰는 제한된 불투명/반투명 표면. 배경과 글자가 충돌하지 않도록 표면 불투명도를 조정하되 글자 뒤에 texture를 두지 않습니다.
3. **Modal surface:** 확인/오류/삭제 등 집중이 필요한 단일 질문. 사용자가 한 행동과 결과를 직접 문장으로 연결합니다. 화면당 중첩 모달 금지.

각 표면 재질은 기본/올림/선택/비활성만 정의합니다. 의미없는 테두리 중첩과 종이 그림자를 반복하지 않습니다.

## 타입과 크기

- 본문은 NotoSansKR 또는 현행 번들 폰트로 유지하고, 숫자 폭/한글 낱자/영문 대문자 높이를 3개 기준 해상도에서 측정합니다.
- 화면이 좁다고 글자를 자동으로 연속 축소하지 않습니다. 줄바꿈, label shorten, 정보 단계화 또는 스크롤로 처리합니다.
- 기능 라벨은 명사/동사를 분명히 합니다. 상태값은 수치+아이콘/이름을 함께 둡니다.
- Stage 1.5의 12–16 “frame units”는 Unity dp나 기기 물리 크기로 환산하지 않습니다. 실제 Android에서 측정 전까지 임시 기준입니다.
- 외부 접근성 기초값: Android 권장 터치 타깃 48dp. Unity frame pixel과 dp는 기기 density/CanvasScaler에 따라 다르므로 물리 검증이 필요합니다.

## 상태 규칙

| 상태 | 표현 |
|---|---|
| Default | 안정된 표면·중립 경계, 분명한 label |
| Focus/Selected | 면/테두리/아이콘 변화 중 최소 둘과 이름/수치 |
| Pressed | 짧은 눌림 변화와 기존 AudioButton 피드백 |
| Disabled | action 불가를 시각적으로 구별하고 가능하면 원인 표시 |
| Pending/Loading | 명확한 대기 표시, 진행값이 있을 때만 progress |
| Error | 무엇이 실패했는지와 플레이어가 할 수 있는 다음 행동 |
| Destructive | 동작/결과를 구체히 설명하고 취소/확인 제공 |
| Empty | 현재 실제 의미의 빈 상태, 다음에 할 수 있는 기능만 제안 |

## 반응형 원칙

| 캔버스 | 정책 |
|---|---|
| 1920×1080 | 기준 시각 레이아웃. 장면과 주요 정보 간격, 최대 패널 폭 설정 |
| 1280×720 | 그룹/열 너비 재배치. 1920을 단순히 0.667배 축소하지 않고 글자와 touch region 가독성 유지 |
| 844×390 | Landscape 모바일 전용 배치. 상태/일시정지/핫바/주 행동 안전영역, 키보드 없는 터치, 좌우 엄지 영역, 상세 pane 축약/전환 고려 |

모든 화면에서 SafeArea와 gesture/cutout 인셋을 먼저 적용합니다. 844 미리보기 frame unit을 Android density-independent pixel로 간주하지 않습니다. 모달은 작은 화면에서 자동 통째 축소되지 않고 내용 재배치/스크롤/분리로 적응합니다.

## 검수 게이트

- 한글·영문 긴 문자열 / 최대 아이템명·수치 / disabled·error·empty 상태 캡처
- 상호작용 가능한 부분은 형태와 명확한 hit-area로 구분
- 대비는 텍스트와 주요 시각 경계 각각 검사; 그라디언트/장면 위 글자는 피하고 필요 시 실측 shadow/surface
- 화면 가림·손가락 가림·오입력은 실제 화면과 물리 Android에서 확인
- 접근성·contrast 통과 여부를 캡처/측정 없이 선언하지 않음
