# 기획·개발 로드맵 — 다음 기획부터 이 순서를 적용

**상태:** 초기 기획. 아래는 '의사결정 순서'로서, 프로토타입·조사는 앞 단계와 병행 가능하다. 임의로 스탯 강화 비용이나 아트 제작부터 확정하지 않는다.

| 순서 | 단계 | 산출물 / 완료 조건 | 현재 |
|---|---|---|---|
| 1 | 콘셉트·핵심 재미 | 장르, 플레이어 역할, 재미 핵심, 차별화 목표 | 방향 합의, 세부 미정 |
| **2** | **핵심 플레이 루프** | **탐험 시작→전진→전투→보상→강화→사망/귀환/환생→재도전 흐름과 목표 정의** | **현재 집중 단계** |

| 8 | 밸런스 검증·본격 제작 | 성장 곡선·드롭·경제·성능 검증 후 콘텐츠·폴리시 확장 | 미착수 |

## 운영 원칙
1. 새 기획 논의의 시작에 **현재 단계와 아직 풀지 못한 이전 단계의 의문**을 확인한다.
2. 원작 환생용병단에서 해당 시스템의 실제 구현을 우선 조사하되 최신성·공식/비공식을 구별한다.
3. 각 결정은 `확정` / `방향 합의` / `검토` / `제외`로 구분하고 `DESIGN_BIBLE.md`에 반영한다.
4. 단계가 완결되지 않았으면 '완료'로 표기하지 않는다. 후속 단계 이야기는 메모만 해 두고 앞 단계로 돌아올 수 있다.
5. 사용자 승인 없이 기술 구현, 보상 수치·강화 비용, 아트 디자인, 스토리를 임의 확정하지 않는다.
6. 가능하면 '이 시스템이 왜 재미있는지'를 실제 작은 프로토타입으로 검증한다. 프로토타입을 만들었다고 본격 제작이 승인된 것은 아니다.

## 당장 다음 논의 — 2단계 핵심 플레이 루프
- **새 방향 기록:** 일반 환생은 기본 0m 재출발이며 시작 거리 사용자 선택도 구상한다(해금·상한 미정). **특수 환생은 보석을 소비해 환생 재화를 수령하면서 거리·골드·골드 강화 등 모든 기존 상태를 그대로 유지하는 것으로 확정**했다. 보석 가격·반복 사용·광고 보상 중첩은 4단계 경제 검증 과제다. 첫 환생 가능 거리 100m는 검증 전 후보. 환생은 첫 해금 이후 자유 선택 방향. 시작 골드 영구 강화는 후보. 환생 거리/횟수 마일스톤은 검토 중.
- **한 번의 탐험은 언제 시작하고 언제 종료되는가?** 일반 환생은 기본 0m 시작, 위치 사용자 선택 가능성을 검토. 특수 환생은 보석 비용과 환생 보상만 처리하고 **기존 탐험 진행 상태를 유지**한다. 사용 조건·반복 수령 경제·보상 중첩·일반 환생 귀환의 관계, 부스트 발동·중첩, 시작 거리 스킵 시 놓친 보상도 미정.
- **진행 거리는 무엇을 뜻하는가?** 연속 거리에서 보스가 다음 구간으로 넘어가는 관문 역할을 하고, 막히면 이전 구간 골드 파밍·강화·재도전 또는 자발적 환생을 택하는 기본 루프는 방향 합의. 정확한 보스 간격·지역 경계·체크포인트 관계와 적정 진행 정체 시간은 미정.
- **사망 후 후퇴는 어떤 비용을 발생시키며, 현재 탐험 진행 상태는 무엇이 유지되는가?** 로그형 후퇴는 방향 확정(`100×ln(1+d/1000)`은 임시 시험식), **부활 HP 전량 회복·골드/골드 강화 유지·일반 몬스터 재등장/재수익·보스 재도전 시 HP 전량 초기화·강제 환생 없음은 확정**. 체크포인트, 부활 지연, 보스 재등장 조건은 여전히 미정.
- **플레이어가 더 강해져야 하는 단기/장기 목표는 무엇인가?**
- **골드, 수집 보상, 영구 성장이 '다음 탐험'으로 어떻게 연결되는가?**

위 다섯 질문의 방향이 결정되기 전에 레벨당 골드 비용·보스 거리·유물 드롭 확률 등을 먼저 확정하지 않는다.

## 향후 GitHub 정리
- `main` 기획 정본 우선.
- 새 개발 콘텐츠가 생기면 원래 계약에 따라 `client/`, `data/`, `tools/`, `tests/`를 필요할 때 생성한다.
- 세부 시스템은 복잡도가 실제 커졌을 때만 문서로 분리한다. 불필요한 다중 정본을 만들지 않는다.
