# Stackfall Mobile Design Bible

상태: `v0.1 — pre-production`

이 문서는 Stackfall Mobile의 최상위 기획 정본이다. 세부 문서는 이 문서를 확장하며, 충돌이 생기면 이 문서를 갱신해 정합성을 회복한다.

---

## 1. 한 문장 정의

> 5~15분짜리 모바일 생존 액션 스테이지를 돌파하고, 전투 방식과 외형을 동시에 바꾸는 기체 부품을 수집·조립·돌파하며, 던전·보스·아레나·랭킹·길드 경쟁으로 장기 성장하는 라이브서비스 액션 RPG.

## 2. 핵심 플레이 판타지

플레이어는 작은 핵/기체에서 시작한다. 전투 중에는 로그라이크식 임시 능력을 조합해 생존하고, 전투 밖에서는 영구 부품을 장착해 기체 자체를 조립한다.

좋은 부품을 얻을수록 숫자만 커지는 것이 아니라 실제 캐릭터의 실루엣·움직임·공격 방식이 변해야 한다.

핵심 감정 흐름:

1. 전투 시작 — 아직 약한 기체
2. 전투 내 레벨업 — 빌드가 빠르게 완성됨
3. 엘리트/보스 — 빌드의 강함을 확인
4. 클리어 — 전리품과 영구 성장 재료 획득
5. 부품 교체/돌파 — 기체 외형과 전투력 변화
6. 새 스테이지/경쟁 콘텐츠 — 성장 이유 재생성

## 3. 게임 기둥

### 3.1 전투

- 세로 화면 우선
- 이동은 한 손 드래그/가상 스틱
- 기본 공격은 자동 조준
- 공격 방식은 부품과 전투 내 스킬에 의해 변화
- 피해야 할 공격은 작은 화면에서도 명확하게 읽혀야 함
- 강한 공격을 표현할 때 무조건 투사체 수만 늘리지 않음
- 보스는 패턴, 장판, 추적, 소환, 돌진 등으로 일반 웨이브와 명확히 구분

### 3.2 스테이지

기본 목표 시간:

- 초반: 5~7분
- 중반: 7~10분
- 일반 후반: 9~12분
- 챕터 보스/특수 스테이지: 12~15분

기본 10분 스테이지 예시:

- 0:00~2:00 — 일반 적, 첫 빌드 형성
- 2:00 — 엘리트
- 2:00~4:30 — 적 조합 변화
- 4:30 — 이벤트/정예
- 6:00 — 중간보스
- 6:00~9:30 — 압박 증가 + 후반 빌드 완성
- 10:00 — 보스

스테이지는 시간만 버티는 구조에 고정하지 않는다. 다음 변형을 사용한다.

- 생존
- 목표 적 처치
- 보스 사냥
- 호위/방어
- 이동 구간
- 영역 점령
- 자원 수집
- 연속 엘리트

단, 조작 복잡도는 모바일 한 손 플레이를 해치지 않는다.

### 3.3 영구 성장

영구 장비는 전통적인 검/갑옷/반지 체계를 쓰지 않는다.

기본 6부품:

1. `코어(Core)` — 핵심 능력, 궁극 계열, 중심 외형
2. `프레임(Frame)` — 체력·방어·충돌, 몸체 실루엣
3. `드라이브(Drive)` — 이동·회피·가속, 추진부 외형
4. `임팩터(Impactor)` — 접촉/충돌/근거리 강화, 전면 구조
5. `오비터(Orbiter)` — 드론·위성·자동공격·보호 장치
6. `리액터(Reactor)` — 스킬 주기·에너지·상태효과·출력

장착 결과는 전투 화면에 즉시 반영한다.

## 4. 부품 희귀도와 성장

초기 희귀도 계층:

`일반 → 고급 → 희귀 → 영웅 → 전설 → 신화 → 초월`

별도 고급 계통으로 `S 프로토타입`을 둔다.

원칙:

- 일반 부품도 초반에는 사용 가능
- S 프로토타입은 단순 스탯 증가가 아니라 빌드 정체성을 제공
- 중복 획득은 승급/돌파에 사용
- 새 부품 획득 때문에 기존 레벨 투자가 통째로 사라지지 않게 함

### 4.1 슬롯 레벨 귀속

부품의 기본 강화 레벨은 아이템이 아니라 슬롯에 귀속한다.

예:

- 코어 슬롯 Lv.53
- 일반 코어 → S 코어 교체
- 새 S 코어도 즉시 Lv.53 적용

새 아이템을 얻었을 때 손해를 느끼게 하지 않고, 반복 과금의 핵심은 희귀도·중복 돌파·고유효과에 둔다.

### 4.2 돌파와 외형 변화

초기 목표 단계:

`S → S★1 → S★2 → 신화 → 신화★1 → 초월`

대표 외형 변화 지점:

- 최초 S 획득: 전용 실루엣
- S★2: 가동부/발광부 강화
- 신화: 구조 확장 + 전용 애니메이션
- 초월: 최종 변형 + 고유 전투 연출

외형 변화는 성능 변화와 같이 보여야 한다.

## 5. S 부품군과 세트 빌드

초기 부품군 후보:

### 과부하

정체성: 이동/공격 속도/연속 처치

- 2세트: 처치 시 단기 가속
- 4세트: 가속 중 공격 강화
- 6세트: 최대 중첩에서 폭주 상태

### 중력붕괴

정체성: 적 집속 + 광역

- 2세트: 약한 흡인
- 4세트: 집속 적 추가 피해
- 6세트: 주기적 대형 중력장

### 요새

정체성: 보호막/생존/반격

### 추적자

정체성: 엘리트·보스 단일 대상 사냥

### 연쇄반응

정체성: 폭발·상태이상 전파

### 공허

정체성: 회피·변위·잔상 공격

원칙:

- 6세트가 항상 정답이 되지 않게 함
- `4+2`, `2+2+2` 혼합 빌드가 실제 메타 선택지가 되게 함
- 메인 스테이지, 보스, 아레나, 탑에서 선호 세팅이 달라지게 함

## 6. 기존 웹 Stackfall에서 가져올 전투 DNA

가져올 것:

- 공격체 중첩에 따라 동작 단계가 확장되는 구조
- 집중 사격
- 공전형 공격
- 연쇄 공격
- 중력/집속
- 왕복/부메랑
- 드론 편대
- 관통 광선
- 보호막/반격
- 적 유형과 장비 조합의 상성

모바일화하면서 폐기/재설계할 것:

- 마우스 포인터 기반 수동 조준
- PC 해상도에서만 읽히는 긴 사거리와 화면 밖 상호작용
- 과도한 투사체 수
- 무한 생존을 전제로 한 8분 단위 장기 스케일링
- 현재 웹판의 피해·주기·경험치 수치 직접 이식

## 7. 전투 내 성장

전투 시작 시 영구 부품은 유지되지만 전투 내 레벨은 매 스테이지 초기화된다.

레벨업 카드 후보 분류:

- 공격 계통 강화
- 부품 고유효과 증폭
- 투사체/공격체 수 변화
- 범위/속도/주기 변화
- 상태이상
- 생존/보호막/회복
- 경험치/자원 리스크-리턴
- 특정 공격의 형태변환

중요 원칙:

- 같은 스킬을 여러 번 고르면 숫자만 증가하지 않고 일정 단계마다 동작이 달라져야 함
- 영구 부품과 전투 내 선택이 시너지를 만들어야 함
- 랜덤성은 강하지만 완전한 운빨만으로 보이지 않게 최소한의 빌드 보정 장치를 둠

## 8. 메인 진행

메인 스테이지는 장기 콘텐츠 해금의 기준이다.

초기 예시:

- Stage 1 — 부품 장착 해금
- Stage 3 — 일반 소환
- Stage 5 — 일일 던전
- Stage 8 — 보스 도전
- Stage 10 — S 프로토타입 소환
- Stage 15 — 무한 탑
- Stage 20 — 아레나
- Stage 25 — 길드
- Stage 30 — 길드 보스
- Stage 40 — 유물/데이터칩 계열
- Stage 50 — 시즌형 콘텐츠

정확한 해금 레벨은 온보딩 길이와 세션 데이터를 보고 최종 조정한다.

## 9. 반복 콘텐츠

### 일일 던전

- 크레딧/골드
- 부품 강화재료
- 승급 재료
- 데이터칩/후기 재료

### 보스 도전

- 제한시간 내 최대 피해
- 일일 제한 횟수
- 개인 기록 + 국가/글로벌 랭킹

### 무한 탑

- 층별 고정/반고정 전투
- 특정 층마다 큰 보상
- 장기 진행도 표시

### 아레나

초기에는 실시간 PvP가 아닌 서버 검증형 비동기 경쟁을 우선한다.

- 무료 일일 도전 횟수
- 추가 티켓
- 주간 티어
- 시즌 보상
- 방어 덱/기체 저장

### 길드

초기 기능:

- 가입/탈퇴
- 출석
- 기부
- 길드 연구
- 길드 상점
- 길드 보스
- 길드 채팅
- 길드 랭킹

후기:

- 길드전
- 협동 원정
- 시즌 영지/레이드

## 10. 랭킹

랭킹 단위:

- 서버/샤드
- 국가
- 글로벌
- 길드

랭킹 항목 후보:

- 전투력
- 메인 스테이지
- 보스 피해량
- 탑 최고층
- 아레나
- 시즌 이벤트
- 길드 총합

랭킹은 성장 동기를 만들지만 핵심 전투 보상 전체를 상위 1%가 독점하는 구조로 만들지 않는다.

## 11. 채팅과 소셜

채널:

- 글로벌
- 국가
- 길드
- 귓속말/친구는 후기 검토

채팅에는 고급 획득 알림, 서버 최초 기록 등 시스템 메시지를 넣을 수 있다.

필수 고려:

- 신고
- 차단
- 금칙어/스팸 제한
- 연령/지역 정책
- 서버 rate limit

## 12. 수익화

수익화는 강하게 설계하되 가격, 확률, 천장, 보상은 투명하게 표시한다.

축:

- 프리미엄 재화
- S 프로토타입 가챠
- 픽업 가챠
- 배틀/시즌 패스
- 성장 기금
- 월정액
- 스타터 패키지
- 챕터 클리어 패키지
- 기간 한정 패키지
- 광고 제거
- 보상형 광고
- 경쟁 콘텐츠 추가 입장권/티켓

초기 가챠 가설:

- S 프로토타입 기본 확률: 약 1~2% 범위에서 검증
- 10회 단위 최소 보장
- S 천장: 40~60회 범위 비교
- 픽업 비율과 천장 이월 여부는 장기 비용 모델을 계산한 뒤 결정

숫자는 `BENCHMARKS.md`와 경제 시뮬레이션 없이 확정하지 않는다.

## 13. 재화

초기 최소 구조:

- `Credits` — 일반 강화
- `Crystal` — 프리미엄 재화
- `Part EXP/Alloy` — 부품 강화
- `Breakthrough Material` — 희귀도/돌파
- 콘텐츠별 토큰 — 아레나/길드/이벤트

재화를 이유 없이 늘리지 않는다. 신규 재화는 별도 플레이 루프나 경제 제어 목적이 있을 때만 추가한다.

## 14. UI 방향

메인 화면 컨셉: `Hangar / 격납고`

중앙에 현재 조립된 기체를 크게 보여준다.

하단 주요 탭 초안:

- 전투
- 기체
- 소환
- 도전
- 길드

기체 화면:

- 6개 부품 슬롯
- 장착 즉시 3D/2D 기체 외형 반영
- 전투력 변화
- 세트 효과
- 비교
- 분해/재조립

가챠 연출은 일반 상자보다 `Salvage / 복원` 테마를 사용한다.

## 15. 미술 방향

핵심은 “작은 기계 생명체가 부품으로 진화한다”는 인상이다.

- 기본 실루엣은 단순하고 읽기 쉬움
- 부품으로 실루엣이 바뀌되 피격 판정 가독성을 해치지 않음
- 고등급은 파티클만 늘리지 않고 구조 자체를 변화
- 작은 모바일 화면에서도 희귀도가 한눈에 보임
- UI와 전투 오브젝트의 색 역할을 분리

## 16. 서버 권위 경계

서버 정본:

- 계정
- 재화
- 가챠 결과
- 인벤토리
- 강화/돌파
- 상품 구매/수령
- 메인 진행도
- 랭킹 제출 검증
- 길드
- 채팅 권한/제재
- 이벤트 상태

클라이언트는 표시와 전투 실행을 담당하되, 서버 가치가 있는 결과는 검증 가능한 형태로 제출한다.

## 17. 모바일 성능 기준

초기 목표:

- 중급 안드로이드에서 안정적인 60fps 목표
- 옵션으로 30fps 저전력 모드 고려
- 대량 적/투사체/VFX는 풀링
- 프레임별 GC 할당 최소화
- 화면 밖 오브젝트 업데이트 예산 관리
- 해상도/이펙트 품질 단계화
- 장시간 세션 발열 확인

## 18. 현재 미확정 항목

아래는 연구/프로토타입 후 확정한다.

- 엔진 최종 선택
- 서버 스택
- 정확한 화면 방향 고정 여부
- 정확한 스테이지 시간 분포
- 부품별 기본/성장 수치
- 가챠 확률/천장/가격
- 무료 유저 월간 재화 공급량
- PvP 전투 시뮬레이션 방식
- 국가/글로벌 샤딩 방식
- 출시 시 부품 수와 S 세트 수
