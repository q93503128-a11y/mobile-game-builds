# Stackfall Mobile 홈/격납고 UI 정본

상태: `v0.2 — first playable shell target`

목적: 전투 프로토타입만 덩그러니 실행하는 테스트를 피하고, 실제 양산형 모바일 RPG의 첫인상에 가까운 `홈 → 편성 → 스테이지 → 전투 → 결과` 흐름을 먼저 만든다. 외부 성공작의 정보구조와 사용감을 참고하되 고유 아트·배치·표현으로 재설계한다.

## 1. 최상위 원칙

- 세로 화면 기준.
- 중앙 주인공은 현재 장착 부품이 실제 반영된 기체.
- 홈은 `격납고`로 표현한다.
- 첫 화면에서 가장 큰 CTA는 현재 메인 스테이지 진입.
- 플레이어에게 개발 상태, 테스트 상태, 내부 버전명, TODO, 디버그 문자열을 노출하지 않는다.
- 참고 게임처럼 `캐릭터/기체 중심 + 상단 재화 + 측면 이벤트 + 하단 영구 탭 + 큰 전투 CTA`라는 검증된 모바일 정보구조를 사용한다.
- 특정 게임의 아트, 아이콘, 문구, 배치 비율을 그대로 복제하지 않는다.
- 첫 사용자 테스트는 전투 화면만으로 진행하지 않는다. 최소한 홈/편성/스테이지 진입/전투/결과 화면이 연결된 뒤 진행한다.

## 2. 첫 테스트용 최소 제품 껍데기

첫 사용자 테스트 전에 반드시 다음 화면이 연결되어야 한다.

1. `홈/격납고`
2. `출격 편성`
3. `메인 스테이지 카드/진입`
4. `전투`
5. `결과`
6. `기체` 탭의 최소 외형 확인 화면

회수/상점/길드/도전은 첫 테스트에서 실제 기능까지 구현할 필요는 없지만, 최종 하단 내비게이션 구조가 어색하지 않은지 확인할 수 있도록 홈 정보구조는 이미 최종 방향에 맞춘다. 미구현 버튼을 플레이어 화면에 `개발 중` 상태로 노출하지 않는다.

## 3. 홈 화면 레이아웃

### 상단 상태 바

- 프로필 아이콘/닉네임
- 전투력
- 에너지(채택 시)
- 크레딧
- 크리스탈
- `+` 버튼을 통한 재화 획득 경로

수치는 한 줄에 과밀하게 몰지 않고 360px 폭에서도 읽히게 한다.

### 중앙 기체 전시 구역

화면 면적의 가장 큰 비중을 사용한다.

- 현재 조립된 기체 실시간 표시
- Core/Frame/Drive/Impactor/Orbiter/Reactor 외형 반영
- Orbiter 공전, Reactor 맥동, Drive 미세 추진 등 가벼운 대기 모션
- 탭 시 기체 상세/격납고로 이동
- 배경은 정비 베이/격납고이며 전투 배경과 명확히 구분

목표 감정은 `내가 키운 것이 화면 중앙에서 계속 보인다`이다.

### 중앙 하단 메인 진행 카드

- 챕터 이름
- `Stage X-Y`
- 보스/환경 대표 아이콘
- 권장 전투력
- 주요 최초 클리어 보상
- 다음 신규 해금이 가까우면 `다음 해금` 정보 표시
- 가장 큰 `출격` CTA

새 무기/지원 능력이 해금되는 스테이지에서는 보상 카드에서 일반 재화보다 신규 능력을 더 크게 강조한다.

### 측면 빠른 진입

왼쪽 또는 오른쪽 한쪽으로 정렬한다.

- 출석
- 임무
- 우편
- 이벤트
- 시즌 패스
- 한정 패키지

첫 화면을 배너 벽으로 만들지 않는다. 동시에 강한 이벤트 CTA는 최대 2개, 나머지는 접이식 스택 또는 작은 아이콘으로 관리한다.

## 4. 하단 기본 탭

1. `전투`
2. `기체`
3. `회수`
4. `도전`
5. `길드`

엄지손가락 접근성을 위해 하단 고정형으로 사용한다.

### 전투

- 홈/격납고와 메인 스테이지 카드
- 출격 편성 진입
- 이전/다음 스테이지 미리보기

### 기체

- 6부품 장착
- 부품 비교
- 슬롯 강화
- 승급/돌파
- 기체 외형 확인
- 전투/보스/아레나 프리셋

### 회수

- 표준 회수
- 프로토타입 공명
- 기간 픽업
- 천장/보장 카운트
- 확률표
- 조율 데이터 교환

### 도전

- 재화 던전
- 보스 랭킹
- 무한 탑
- 아레나
- 기간 이벤트

### 길드

- 길드 홈
- 출석/기부
- 연구/상점
- 길드 보스
- 채팅/랭킹

## 5. 출격 편성 화면

메인 스테이지의 `출격`을 누르면 바로 전투로 던지지 않고 한 번의 간결한 편성 화면을 거친다.

표시:
- 현재 기체/전투력
- 6부품 요약
- 액티브 후보 덱
- 지원 후보 덱
- 추천 빌드 태그
- 스테이지 주요 적/보스 특징
- 최종 `전투 시작` 버튼

편성 자체가 긴 관리 작업이 되지 않게 1~2탭으로 프리셋을 바꿀 수 있어야 한다.

세부 규칙은 `ACTIVE_LOADOUT_V0.md`를 따른다.

## 6. 기체 화면

중앙: 조립 기체
주변 6방향 슬롯:
- Core
- Frame
- Drive
- Impactor
- Orbiter
- Reactor

부품 선택 시:
- 현재 vs 후보 비교
- 기본 스탯 차이
- 고유효과
- 세트 효과
- 외형 미리보기
- 장착
- 강화/돌파 접근

자동 추천은 `전투력 최대`와 `현재 빌드 추천`을 구분한다.

## 7. 프리셋

기본 3개:
- 메인
- 보스
- 아레나

프리셋 저장 대상:
- 6부품
- 액티브 후보 덱
- 지원 후보 덱
- 후기 데이터칩/유물 계통

슬롯 레벨은 공유한다.

## 8. 클리어 결과 화면

전투 종료 즉시 홈으로 튕기지 않는다.

표시:
- 클리어/실패
- 획득 재화
- 획득 부품/재료
- 신규 기록
- 신규 해금
- 다음 스테이지 미리보기

최초 클리어에서 신규 액티브/지원 능력이 열렸다면 결과 화면 최상단에 전용 카드로 보여준다.

CTA:
- `다음 스테이지`
- `격납고`

실패 시에는 강제 결제 팝업 대신 권장 성장 경로를 1~2개만 보여준다.

## 9. 상품/알림 노출 규칙

상품은 성장 맥락과 연결한다.

예:
- 첫 S 획득 후 S 성장 패키지
- 챕터 보스 최초 클리어 후 챕터 패키지
- 시즌 시작 시 패스

금지:
- 전투 중 구매 팝업
- 실패 직후 닫기 어려운 다중 팝업
- 무료/유료 버튼 혼동
- 단순 상품 존재만으로 영구 빨간 점

빨간 점은 실제 받을 보상/무료 행동/미확인 변화에만 사용한다.

## 10. 모바일 접근성/가독성

- 핵심 터치 목표 최소 48dp 수준
- 주요 CTA는 하단 60% 영역 우선
- Safe Area 준수
- 희귀도/상태를 색만으로 전달하지 않음
- 360×640급 화면에서도 하단 탭과 출격 CTA가 겹치지 않음
- 홈에서는 기체가 UI보다 먼저 눈에 들어와야 함

## 11. 첫 사용자 테스트 합격 조건

사용자에게 첫 Unity 테스트를 요청하기 전에:
- 홈/격납고가 모바일 라이브서비스 게임의 메인 화면처럼 보임
- 중앙 기체, 상단 재화, 하단 탭, 메인 스테이지 CTA가 존재
- 출격 편성 화면이 연결됨
- 전투 진입과 결과 복귀가 연결됨
- 전투에서 이동/자동조준/3종 공격/3택/엘리트/보스가 작동
- 플레이어 화면에 개발자용 문구가 없음
- Unity import/compile 오류 0 확인 준비가 됨

그때 사용자에게 `이제 테스트`라고 명확히 요청한다.
