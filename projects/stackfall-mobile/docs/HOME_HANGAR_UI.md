# Stackfall Mobile 홈/격납고 UI 정본

상태: `v0.7 — first-test source gate hardened, Unity verification next`

목적: 전투 프로토타입만 덩그러니 실행하는 테스트를 피하고, 실제 양산형 모바일 RPG의 첫인상에 가까운 `홈 → 편성 → 스테이지 → 전투 → 결과` 흐름을 먼저 만든다. 외부 성공작의 정보구조와 사용감을 참고하되 고유 아트·배치·표현으로 재설계한다.

## 1. 최상위 원칙

- 세로 화면 기준.
- 중앙 주인공은 현재 장착 부품이 실제 반영된 기체.
- 홈은 `격납고`로 표현한다.
- 첫 화면에서 가장 큰 CTA는 현재 메인 스테이지 진입.
- 플레이어에게 개발 상태, 테스트 상태, 내부 버전명, TODO, 디버그 문자열을 노출하지 않는다.
- 참고 게임처럼 `캐릭터/기체 중심 + 상단 재화 + 측면 이벤트 + 하단 영구 탭 + 큰 전투 CTA`라는 검증된 모바일 정보구조를 사용한다.
- 특정 게임의 아트, 아이콘, 문구, 배치 비율을 그대로 복제하지 않는다.
- 첫 사용자 테스트는 전투 화면만으로 진행하지 않는다. 최소한 홈/편성/스테이지 진입/전투/결과 화면이 연결된 뒤 진행한다.

## 2. 첫 테스트용 최소 제품 껍데기

첫 사용자 테스트 전에 반드시 다음 화면이 연결되어야 한다.

1. `홈/격납고`
2. `출격 편성`
3. `메인 스테이지 카드/진입`
4. `전투`
5. `결과`
6. `기체` 탭의 최소 외형 확인 화면

회수/상점/길드/도전은 첫 테스트에서 실제 기능까지 구현할 필요는 없지만, 최종 하단 내비게이션 구조가 어색하지 않은지 확인할 수 있도록 홈 정보구조는 이미 최종 방향에 맞춘다. 미구현 버튼을 플레이어 화면에 `개발 중` 상태로 노출하지 않는다.

## 3. 홈 화면 레이아웃

### 상단 상태 바

- 프로필 아이콘/닉네임
- 전투력
- 에너지(채택 시)
- 크레딧
- 크리스탈
- `+` 버튼을 통한 재화 획득 경로

수치는 한 줄에 과밀하게 몰지 않고 360px 폭에서도 읽히게 한다.

### 중앙 기체 전시 구역

화면 면적의 가장 큰 비중을 사용한다.

- 현재 조립된 기체 실시간 표시
- Core/Frame/Drive/Impactor/Orbiter/Reactor 외형 반영
- Orbiter 공전, Reactor 맥동, Drive 미세 추진 등 가벼운 대기 모션
- 탭 시 기체 상세/격납고로 이동
- 배경은 정비 베이/격납고이며 전투 배경과 명확히 구분

목표 감정은 `내가 키운 것이 화면 중앙에서 계속 보인다`이다.

### 중앙 하단 메인 진행 카드

- 챕터 이름
- `Stage X-Y`
- 보스/환경 대표 아이콘
- 권장 전투력
- 주요 최초 클리어 보상
- 다음 신규 해금이 가까우면 `다음 해금` 정보 표시
- 가장 큰 `출격` CTA

새 무기/지원 능력이 해금되는 스테이지에서는 보상 카드에서 일반 재화보다 신규 능력을 더 크게 강조한다.

### 측면 빠른 진입

왼쪽 또는 오른쪽 한쪽으로 정렬한다.

- 출석
- 임무
- 우편
- 이벤트
- 시즌 패스
- 한정 패키지

첫 화면을 배너 벽으로 만들지 않는다. 동시에 강한 이벤트 CTA는 최대 2개, 나머지는 접이식 스택 또는 작은 아이콘으로 관리한다.

## 4. 하단 기본 탭

1. `전투`
2. `기체`
3. `회수`
4. `도전`
5. `길드`

엄지손가락 접근성을 위해 하단 고정형으로 사용한다.

### 전투

- 홈/격납고와 메인 스테이지 카드
- 출격 편성 진입
- 이전/다음 스테이지 미리보기

### 기체

- 6부품 장착
- 부품 비교
- 슬롯 강화
- 승급/돌파
- 기체 외형 확인
- 전투/보스/아레나 프리셋

### 회수

- 표준 회수
- 프로토타입 공명
- 기간 픽업
- 천장/보장 카운트
- 확률표
- 조율 데이터 교환

### 도전

- 재화 던전
- 보스 랭킹
- 무한 탑
- 아레나
- 기간 이벤트

### 길드

- 길드 홈
- 출석/기부
- 연구/상점
- 길드 보스
- 채팅/랭킹

## 5. 출격 편성 화면

메인 스테이지의 `출격`을 누르면 바로 전투로 던지지 않고 한 번의 간결한 편성 화면을 거친다.

표시:
- 현재 기체/전투력
- 6부품 요약
- 액티브 후보 덱
- 지원 후보 덱
- 추천 빌드 태그
- 스테이지 주요 적/보스 특징
- 최종 `전투 시작` 버튼

편성 자체가 긴 관리 작업이 되지 않게 1~2탭으로 프리셋을 바꿀 수 있어야 한다.

세부 규칙은 `ACTIVE_LOADOUT_V0.md`를 따른다.

## 6. 기체 화면

중앙: 조립 기체
주변 6방향 슬롯:
- Core
- Frame
- Drive
- Impactor
- Orbiter
- Reactor

부품 선택 시:
- 현재 vs 후보 비교
- 기본 스탯 차이
- 고유효과
- 세트 효과
- 외형 미리보기
- 장착
- 강화/돌파 접근

자동 추천은 `전투력 최대`와 `현재 빌드 추천`을 구분한다.

## 7. 프리셋

기본 3개:
- 메인
- 보스
- 아레나

프리셋 저장 대상:
- 6부품
- 액티브 후보 덱
- 지원 후보 덱
- 후기 데이터칩/유물 계통

슬롯 레벨은 공유한다.

## 8. 클리어 결과 화면

전투 종료 즉시 홈으로 튕기지 않는다.

표시:
- 클리어/실패
- 획득 재화
- 획득 부품/재료
- 신규 기록
- 신규 해금
- 다음 스테이지 미리보기

최초 클리어에서 신규 액티브/지원 능력이 열렸다면 결과 화면 최상단에 전용 카드로 보여준다.

CTA:
- `다음 스테이지`
- `격납고`

실패 시에는 강제 결제 팝업 대신 권장 성장 경로를 1~2개만 보여준다.

## 9. 상품/알림 노출 규칙

상품은 성장 맥락과 연결한다.

예:
- 첫 S 획득 후 S 성장 패키지
- 챕터 보스 최초 클리어 후 챕터 패키지
- 시즌 시작 시 패스

금지:
- 전투 중 구매 팝업
- 실패 직후 닫기 어려운 다중 팝업
- 무료/유료 버튼 혼동
- 단순 상품 존재만으로 영구 빨간 점

빨간 점은 실제 받을 보상/무료 행동/미확인 변화에만 사용한다.

## 10. 모바일 접근성/가독성

- 핵심 터치 목표 최소 48dp 수준
- 주요 CTA는 하단 60% 영역 우선
- Safe Area 준수
- 희귀도/상태를 색만으로 전달하지 않음
- 360×640급 화면에서도 하단 탭과 출격 CTA가 겹치지 않음
- 홈에서는 기체가 UI보다 먼저 눈에 들어와야 함

## 11. 첫 사용자 테스트 합격 조건

사용자에게 첫 Unity 테스트를 요청하기 전에:
- 홈/격납고가 모바일 라이브서비스 게임의 메인 화면처럼 보임
- 중앙 기체, 상단 재화, 하단 탭, 메인 스테이지 CTA가 존재
- 출격 편성 화면이 연결됨
- 전투 진입과 결과 복귀가 연결됨
- 전투에서 이동/자동조준/3종 공격/3택/엘리트/보스가 작동
- 플레이어 화면에 개발자용 문구가 없음
- Unity import/compile 오류 0 확인 준비가 됨

그때 사용자에게 `이제 테스트`라고 명확히 요청한다.


## 12. Phase 1B 런타임 연결 상태

현재 C# 정본에는 다음 흐름이 연결되어 있다.

`격납고 → 출격 편성 → 전투 → 결과 → 다음 스테이지/격납고`

구현 원칙:
- 앱 시작 시 전투를 바로 생성하지 않고 격납고를 먼저 표시
- 전투 진입 시에만 전투 런타임을 생성하고 종료 시 정리
- 액티브 8칸/지원 8칸 후보 덱을 확장 가능한 카드 구조로 표시
- 해금표와 동일한 다음 능력 해금 정보를 홈/결과에 사용
- 기체 화면에서 6부품 장착 구조와 현재 조립 외형을 확인 가능
- 전투 기체도 단순 원형 대신 Core/Frame/Drive/Impactor/Orbiter/Reactor가 구분되는 조립 실루엣 사용
- 화면 최외곽은 `Screen.safeArea`를 기준으로 패딩 적용

이 단계의 전투력 표시는 레이아웃 연결을 위한 프로필 표시값이며 영구 부품/경제 밸런스 수치의 정본으로 사용하지 않는다. 실제 전투력 산식은 Phase 3 부품 시스템에서 데이터 기반으로 연결한다.

아직 완료로 판정하지 않는 항목:
- Unity 6000.3.19f1 import/compile
- 실제 360×640 이상 대표 해상도 가독성
- Play Mode에서 전체 화면 전환과 버튼 입력
- Console error 0

위 항목은 첫 사용자 테스트 게이트에서 확인한다.


## 13. Phase 1B 첫 플레이 범위

- 현재 제품 껍데기 검증 범위의 실제 진행은 `Stage 1 → Stage 2`까지 연다.
- `Stage 3+` 해금표는 정본에 유지하지만, 해당 신규 액티브가 실제 전투 런타임에 들어오기 전에는 플레이어 진행으로 먼저 노출하지 않는다.
- Stage 2 클리어 후에는 동일 스테이지 재출격 또는 격납고 복귀가 가능하다.
- 이 경계는 장기 콘텐츠 수를 줄이는 결정이 아니라 UI 해금 상태와 실제 전투 가능 콘텐츠의 불일치를 막기 위한 통합 게이트다.


## 14. 완성형 외형 레이어

첫 테스트 이전이라도 플레이어가 보는 제품 화면은 단순 기능 버튼 모음처럼 보이지 않게 한다. 실제 서버/결제 기능의 완성 여부와 별개로 화면 정보구조는 출시형 모바일 라이브서비스 게임에 가까운 밀도를 가진다.

현재 소스에 추가된 외형 표면:

- 우주 항로 로딩 화면 + 진행 표시 + 전술 팁
- 우편함
- 일일/주간/업적 탭 구조를 가진 임무 화면
- 추천/일일/재화 탭 구조의 상점 화면
- 프로토타입 공명 소환 화면
- 설정 화면
- 홈의 임무/우편/상점/소환 빠른 진입
- 이벤트 배너 및 플레이어 상태 카드

외형용 화면이라도 경제 정본과 충돌하는 확률/천장/소환 가격을 임의로 만들지 않는다. 소환 화면은 현재 정본의 `1회 300 크리스탈 / 10회 2,700 크리스탈 / S 1.5% / 50회 S 천장 / 픽업 S 60%` 규칙을 표시한다. 아직 가격이 확정되지 않은 현금 패키지는 임의 원화 가격을 표시하지 않는다.

기능 아이콘은 상업 이용이 확인된 외부 CC0 자산을 사용한다. 출처와 체크섬은 `EXTERNAL_UI_ASSETS.md`를 정본으로 한다.

현재 우편/임무/상점의 목록 데이터는 UI 흐름 검증용 초기 로컬 상태다. 장기 저장, 서버 보상 수령, 실제 결제, 서버 권위 소환은 각각 경제/서버 단계에서 연결한다. 플레이어 화면에는 이러한 내부 구현 상태를 설명하는 개발자 문구를 노출하지 않는다.

## 15. 완성형 외형 허브 확장

Unity 첫 사용자 테스트 전에 모바일 게임의 빈 화면처럼 보이는 구간을 줄이기 위해 다음 화면 껍데기를 연결한다. 실제 경제/서버 권위 기능이 아직 없는 화면은 확정되지 않은 현금 가격이나 재화 수치를 임의로 만들지 않는다.

- 파일럿 프로필: 대표 기체, 현재 진행, 작전 기록, 프로필 장식
- 7일 출석 보급: 7일 보상 카드와 오늘 보급 강조
- 이벤트 허브: 심우주 회수 작전, 출석, 주간 임무, 교환소 진입
- 메인 작전/챕터 선택: 초기 8챕터의 이름, 핵심 위험, 해금 구간 미리보기
- 부품 보관함: 6슬롯 탭, 현재 장착, 일반/S 프로토타입 등급 카드, 슬롯 강화 공유 안내
- 도전 허브: 크레딧 채굴장, 정밀부품 회수전, 보스 격파전, 무한 탑, 아레나
- 길드 허브: 출석, 기부, 길드 보스, 채팅, 연구 기능 미리보기

하단 `회수 / 도전 / 길드` 탭은 단순 잠금 안내 한 장으로 끝내지 않고 각 시스템의 실제 최종 정보구조를 미리 보여준다. 잠긴 기능은 플레이어에게 자연스러운 해금 조건으로만 표시한다.


## 16. Phase 1B 상호작용 셸 상태

겉모습만 존재하던 메타 화면을 첫 플레이 전 검수 가능한 상호작용 셸로 한 단계 올렸다.

현재 연결:
- 상단 프로필 영역 탭 → 파일럿 프로필
- 우편 개별 수령 / 전체 수령과 수령 상태 유지
- 임무 `일일 / 주간 / 업적` 실제 탭 전환과 보상 수령 피드백
- 상점 `추천 / 일일 / 재화` 실제 탭 전환, 무료 일일 보급 1회 상태 유지
- 출석 DAY 1 보급 수령 상태 유지
- 프로토타입 공명에서 현재 보유 크리스탈 부족 시 정상 안내 후 상점 이동 선택지 제공
- 설정의 BGM / 효과음 / 진동 / 절전 토글과 그래픽 품질 선택을 셸 세션 동안 유지
- 부품 보관함에서 6슬롯 탭 전환, 부품 선택, 장착 상태 변경 가능
- 장착 변경 결과를 기체 화면과 출격 편성의 6부품 요약에 즉시 반영
- 하단 `회수`는 단일 픽업 배너가 아니라 `표준 회수 / 프로토타입 공명 / 목표 부품 조율` 허브로 진입
- 공용 모달과 토스트로 보상/부족 재화/정보 확인 피드백 제공

이 상태는 실제 계정·서버·영구 저장 구현이 아니다. 영구 경제/가챠 결과/인벤토리 권위는 기존 로드맵의 서버·데이터 단계에서 구현한다. 현재 목적은 첫 Unity 테스트 전에 플레이어가 누르는 주요 셸 요소가 무반응 장식으로 남지 않게 하는 것이다.


## 17. 첫 Unity 검증 직전 하드닝

첫 사용자 테스트 직전에는 화면 수를 더 늘리지 않고 실제 Unity import/Play Mode에서 문제가 되기 쉬운 런타임 UI 경계를 먼저 고정한다.

- Shell PanelSettings는 `1080×1920`, `ScaleWithScreenSize`, `MatchWidthOrHeight`, width match(`match = 0`)를 명시한다.
- Shell 패널 정렬값은 50, 전투 HUD 패널 정렬값은 100으로 분리한다. 서로 다른 PanelSettings를 사용하므로 패널 자체의 sorting order도 명시한다.
- Safe Area 좌표 변환은 width-match와 같은 단일 스케일을 사용한다.
- 전투 HUD에도 Safe Area 패딩을 적용해 노치/상단 카메라 홀과 선체·타이머 HUD가 겹치지 않게 한다.
- 기체 화면의 `메인 / 보스 / 아레나` 프리셋 표시는 무반응 장식이 아니라 실제 선택 상태를 바꾼다.
- 프로젝트 첫 import 시 Editor bootstrap이 빈 `Assets/Scenes/Bootstrap.unity`를 생성하고 Build Settings의 유일한 시작 Scene으로 등록한다. 실제 런타임은 기존 `RuntimeInitializeOnLoadMethod`가 구성한다.
- 이 자동 생성은 Unity Editor가 실제로 실행될 때 수행되므로, source preflight 통과만으로 Scene import 성공을 주장하지 않는다.

이 단계 이후 source-only 검사로 얻을 수 있는 정보의 한계에 도달하면 첫 사용자 Unity 검증 게이트를 연다.
