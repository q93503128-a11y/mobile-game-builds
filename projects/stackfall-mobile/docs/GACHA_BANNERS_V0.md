# Stackfall Mobile 소환/픽업 구조 V0

상태: `Phase 0 내부 기획 정본`

목적: S 프로토타입 6부품 구조에서 원하는 부품을 노릴 수 있게 하면서도 중복 성장과 장기 수집 수요를 유지한다.

기본 확률과 천장은 `BALANCE_V0.md`를 따른다.

## 1. 소환 종류

### 1.1 표준 회수

상시 배너.

- 전체 일반~영웅 부품
- 상시 S 프로토타입 풀
- 기본 S 확률 1.5%
- 50회 S 천장
- 별도 픽업 없음
- 무료/일반 소환권의 주요 사용처

역할:
- 신규 유저의 폭넓은 부품 확보
- 이벤트/던전에서 지급하는 일반 키 사용처
- 오래된 S 세트의 영구 획득 경로

### 1.2 프로토타입 공명

주력 픽업 배너.

한 번에 S 세트 1개를 대표 세트로 지정한다.

예:
- 과부하 공명
- 중력붕괴 공명
- 요새 공명
- 공허 공명

규칙:
- S 기본 확률 1.5%
- 50회 S 천장
- S 등장 시 대표 세트 확률 60%
- 대표 세트에 실패했다면 다음 S는 대표 세트 확정
- 대표 세트 보장은 같은 배너 계열에서 이월
- S 천장은 배너 회전 후에도 같은 `프로토타입 공명` 계열 안에서 이월

### 1.3 목표 부품 조율

프로토타입 공명 배너에서 플레이어가 대표 세트의 6부품 중 1개를 목표로 선택한다.

대표 세트 S가 등장했을 때:
- 목표 부품: 50%
- 나머지 5부품: 합계 50%, 균등 분배

목표 부품을 얻지 못한 S 획득 1회마다 `조율 데이터` 1 획득.

- 조율 데이터 3개로 현재 대표 세트의 목표 부품 1개 확정 교환 가능
- 조율 데이터는 배너 종료 후에도 유지
- 목표를 바꿔도 기존 조율 데이터는 사라지지 않음
- 이미 초월 완료한 부품도 목표로 선택할 수 있으나 UI에서 완료 상태를 명확히 표시

목적:
- 고래 유저에게 명확한 목표 지출 경로 제공
- 완전 무작위 6슬롯 때문에 특정 1부품이 끝없이 안 나오는 문제 완화
- 중복 9개 성장 구조와 양립

## 2. 천장 계산 원칙

50회 S 천장은 `S가 하나도 나오지 않은 연속 소환 수`를 기준으로 한다.

- S 조기 등장 시 카운트 0으로 리셋
- 50번째에는 확률 판정 전에 S 보장
- 10회 소환은 1회 소환 10번을 묶어 실행한 것과 동일한 결과 규칙 사용
- 10회 영웅 이상 보장은 S 천장 판정을 침범하지 않음

천장과 픽업 보장 상태는 서버 정본이다.

## 3. 중복 부품 처리

S 중복은 우선 해당 부품 돌파에 사용한다.

초월 완료 후 추가 중복:

- `프로토타입 코어 조각`으로 변환 가능
- 일정 수량으로 같은 세트의 S 부품 교환
- 교환 비율은 직접 뽑기보다 효율이 낮아야 하지만 완전 폐기물은 되지 않게 함

V0 연구안:
- 초월 이후 S 중복 1개 → 코어 조각 40
- 같은 세트 S 선택 상자 → 코어 조각 120

즉 초월 후 잘못 뜬 S 3개가 원하는 S 1개 가치에 해당하는 안을 우선 시험한다.

## 4. 일반 부품 합성

일반~영웅 부품은 낮은 등급 중복을 재료로 사용한다.

원칙:
- 부품별 개별 레벨은 없고 슬롯 레벨이 별도 존재
- 합성 실패 없음
- 확률형 강화 없음
- 저등급 부품은 상위 일반 부품 성장 재료로 계속 가치 유지
- S 프로토타입은 일반 부품만으로 직접 제작할 수 없음

## 5. 무료/유료 소환권

소환권은 목적을 구분한다.

- `회수 키`: 표준 회수 전용
- `공명 키`: 프로토타입 공명에서 크리스탈 대신 사용 가능

공명 키는 이벤트, 시즌패스, 고난도 콘텐츠, 유료 패키지의 높은 가치 보상으로 사용한다.

무료 유저에게 공명 키를 완전히 차단하지 않는다.

## 6. 배너 운영

초기 운영 가설:
- 대표 S 세트 픽업: 14일
- 두 개 이상의 픽업 배너를 동시에 과도하게 늘리지 않음
- 신규 세트 출시 후 일정 기간 지나면 표준 풀 또는 아카이브 회수에 편입
- 과거 세트를 영구적으로 획득 불가능하게 만들지 않는 방향 우선

신규 세트 추가로 상시 풀 희석이 심해지면 다음을 검토한다.

- 시대/시즌별 아카이브 배너
- 세트 그룹 선택
- 위시리스트
- S 교환 상점

## 7. 소환 연출

세계관 표현: `폐기 기체/우주 잔해에서 부품을 회수하고 재구성한다`.

기본 흐름:
1. 회수 신호 탐지
2. 기계 팔/스캔 링이 잔해를 분해
3. 희귀도에 따라 내부 에너지 색/형태 변화
4. S 등장 시 부품 전체 실루엣 공개
5. 신규 S면 현재 기체에 짧게 장착된 모습을 미리 보여줌

상자 개봉 화면을 그대로 복제하지 않는다.

10회 결과는 한 화면에서 빠르게 확인 가능해야 하며 이미 본 연출은 건너뛸 수 있다.

## 8. 소환 UI에서 반드시 보여줄 정보

- 각 희귀도 확률
- S 확률
- 현재 S 천장 카운트
- 대표 세트 확률
- 픽업 실패 후 확정 상태
- 선택한 목표 부품
- 보유 조율 데이터
- 중복 부품의 사용처

확률과 천장은 메뉴 깊숙한 곳에 숨기지 않는다.

## 9. 서버 권위

서버가 결정:
- 소환 결과
- 천장 카운트
- 대표 세트 보장 상태
- 조율 데이터
- 재화 차감
- 아이템 지급

클라이언트는 요청과 연출만 담당한다.

네트워크 재시도 시 중복 결제를 막기 위해 각 소환 요청에 idempotency key를 사용한다.

## 10. 밸런스 검증 항목

구현 전/후 다음을 시뮬레이션한다.

- 목표 S 1개 평균/중앙값/90/95/99 분위 뽑기 수
- 목표 S 9개 평균 비용
- 6슬롯 한 세트 초월 예상 기간
- 무과금 30/90/180일 성장
- 월정액+패스 유저 성장
- 신규 세트 추가 시 상시 풀 희석률
- 조율 데이터 교환이 직접 뽑기 가치를 과도하게 잠식하는지
