# Stackfall Mobile 개발 로드맵

현재 단계: `Pre-production`

원칙: 콘텐츠를 많이 만드는 것보다 먼저 코어 전투와 데이터 구조가 맞는지 검증한다. 임시 구현을 쌓은 뒤 나중에 갈아엎는 방식은 피한다.

## Phase 0 — 정본/연구 고정

목표:
- 기존 웹 Stackfall 기능 목록 전수 분류
- 경쟁작 수치/경제/콘텐츠 벤치마크
- Design Bible 정합성 점검
- 모바일 플랫폼 요구사항 정리

완료 조건:
- 웹판 주요 무기/패시브/보스/이벤트가 `KEEP DNA / MOBILE REDESIGN / META CONVERT / DROP / RESEARCH`로 분류됨
- 부품 6슬롯 책임이 겹치지 않음
- 첫 경제 시뮬레이션 입력값 범위가 준비됨

## Phase 1 — 전투 프로토타입

목표:
- 모바일 이동
- 자동 조준
- 적 스폰
- 경험치/레벨업
- 3종 이상 공격 방식
- 엘리트 1종
- 보스 1종
- 5~10분 스테이지 완주

검증:
- 작은 화면에서 공격/위험 구분 가능
- 한 손 플레이 가능
- 자동 조준이 답답하지 않음
- 투사체 수를 올리지 않아도 성장 체감이 남
- 10분 플레이 동안 메모리/프레임 악화가 누적되지 않음

이 단계에서는 상점/가챠/길드 UI를 먼저 만들지 않는다.

## Phase 2 — 데이터 주도 콘텐츠 구조

목표:
- 적/웨이브/스테이지/부품/스킬을 코드 하드코딩 대신 데이터로 정의
- 데이터 스키마
- ID 중복/누락 참조/수치 범위 검사
- 밸런스 시뮬레이션 도구 기반

완료 조건:
- 새 스테이지를 핵심 코드 수정 없이 추가 가능
- 새 부품을 데이터+필요한 고유 동작 모듈로 추가 가능
- 경제 숫자를 한 정본에서 관리

## Phase 3 — 영구 부품 시스템

목표:
- 코어/프레임/드라이브/임팩터/오비터/리액터
- 장착/교체
- 슬롯 레벨
- 등급
- 합성/돌파
- 세트 효과
- 외형 변형
- 프리셋

검증:
- 새 부품 획득 시 기존 기본 강화 투자가 유지됨
- 중복 부품 가치가 명확함
- 6세트만 정답이 되지 않음
- 외형 변화가 실제 전투 가독성을 해치지 않음

## Phase 4 — 메인 진행/경제

목표:
- 메인 스테이지 진행도
- 기본 재화
- 보상 테이블
- 일일/주간 공급량
- 에너지 사용 여부 확정
- 무료 유저 성장곡선
- 소과금/중과금/고과금 모델 비교

필수 산출:
- 30일 경제 시뮬레이션
- S 부품 기대 획득 기간
- 6슬롯 성장 기간
- 재화 source/sink 표

## Phase 5 — 가챠/상점/수익화

목표:
- 일반 소환
- S 프로토타입 픽업
- 천장
- 배너 이월
- 패키지
- 성장 기금
- 월정액
- 시즌 패스
- 보상형 광고
- 광고 제거

검증:
- 확률 합 100%
- 천장 경계 테스트
- 중복 결제/중복 수령 방지
- 잘못된 가격/상품 ID fail-closed
- 서버가 결과를 결정

## Phase 6 — 반복 PvE

순서:
1. 재화 던전
2. 보스 피해 도전
3. 무한 탑
4. 고난도 변형 스테이지

각 콘텐츠는 고유 성장 재료 또는 성장 효율 차이를 가져야 한다.

## Phase 7 — 계정/서버/랭킹

목표:
- 계정 저장
- 서버 권위 재화/인벤토리
- 전투 결과 제출/검증
- 국가/글로벌 랭킹
- 시즌 리셋

랭킹은 치트 제출과 재전송을 기본 위협으로 가정한다.

## Phase 8 — 아레나

초기:
- 비동기 PvP
- 방어 기체 스냅샷
- 일일 티켓
- 주간 티어
- 시즌 보상

실시간 PvP는 초기 범위에서 제외하고 별도 기술 검증 후 결정한다.

## Phase 9 — 길드/채팅

목표:
- 길드 생성/검색/가입
- 출석/기부
- 길드 연구/상점
- 길드 보스
- 길드 랭킹
- 글로벌/국가/길드 채팅
- 신고/차단/스팸 제한

길드전은 이 기본층이 안정된 뒤 추가한다.

## Phase 10 — 라이브서비스 도구

목표:
- 원격 밸런스 데이터
- 이벤트 기간 설정
- 상품/배너 일정
- 공지
- 서버 feature flag
- 로그/운영 감사

운영 데이터 변경이 앱 업데이트 없이 가능하더라도 스키마와 범위 검증을 통과해야 한다.

## Phase 11 — 콘텐츠 생산

출시 후보 규모는 프로토타입 결과로 확정한다.

초기 가설:
- 여러 챕터
- 충분한 메인 스테이지
- 6부품 슬롯
- 복수 일반 부품군
- S 프로토타입 세트 여러 개
- 보스/엘리트 변형
- 던전/탑/아레나/길드

스테이지 수를 채우기 위해 수동 복붙하지 않는다. 웨이브/적 조합/환경 규칙을 데이터화해 제작 효율을 높인다.

## Phase 12 — 출시 게이트

필수:
- 크래시/ANR 점검
- 저장/복구
- 결제 검증
- 가챠 확률 표시
- 개인정보/채팅 정책
- 저사양 성능
- 발열/배터리
- 다양한 화면비
- 앱 중단/복귀
- 서버 장애 시 UX
- 계정 이전/복구 정책
- 치트/재화 위변조 기본 방어

## 작업 순서 금지사항

다음 순서를 금지한다.

- 코어 전투 검증 전 대량 스테이지 제작
- 경제 시뮬레이션 전 상품 가격 대량 확정
- 서버 권위 설계 전 클라이언트 가챠 구현
- 길드 기본 기능 전 길드전 구현
- 프로파일링 전 대량 VFX 콘텐츠 추가
- 구 구현 삭제 없이 새 구현 병렬 누적
