# Stackfall Mobile 개발 로드맵

현재 단계: `Phase 1 combat core complete → mobile shell integration`

엔진: `Unity 6000.3.19f1 / C#`

원칙: 콘텐츠를 많이 만드는 것보다 먼저 코어 전투와 데이터 구조가 맞는지 검증한다. 임시 구현을 쌓은 뒤 나중에 갈아엎는 방식은 피한다. Unity는 매 작업마다 열지 않되, 사용자 첫 테스트는 단순 전투 원형이 아니라 모바일 게임으로서 최소 구색을 갖춘 뒤 진행한다.

## Phase 0 — 정본/연구 고정 ✅

완료:
- 기존 웹 Stackfall 기능 전수 분류
- 경쟁작 수치/경제/콘텐츠 벤치마크
- 모바일 플랫폼 요구사항
- Unity 프로젝트 구조/검증 정책
- 6부품/S 24부품/가챠/경제 V0
- 12개 공격 6단 진화
- Stage 1~50 능력 순차 해금
- 액티브/지원 후보 덱 구조
- 초기 8챕터/적/엘리트/보스
- 홈/격납고 정보구조
- 던전/랭킹/탑/아레나/길드 기획
- 길드/채팅/모더레이션
- 데이터 스키마/정적 검증기

## Phase 1A — 전투 코어 소스 ✅

소스 구현:
- 모바일 드래그 이동 + 키보드 확인 입력
- 자동 조준
- 적/경험치/투사체/중력장 풀링
- 일반 웨이브/엘리트/5분 보스
- 엘리트 예고 돌진
- 보스 광역 펄스/돌진
- 경험치/레벨업/3택
- 코어 펄스 / 펄스 블레이드 / 중력 우물
- 선체/동력/타이머/보스 체력 HUD
- 클리어/실패
- 위험 시각표현/판정 반경 정합
- Runtime source hygiene + Actions 정적 검사

이 코어는 아직 사용자 첫 플레이 테스트 대상으로 넘기지 않는다.

## Phase 1B — 모바일 제품 껍데기 ← NEXT

첫 테스트 전에 구현할 최소 구색:

1. 홈/격납고 메인 화면
2. 상단 프로필/전투력/재화 바
3. 중앙 조립 기체 전시
4. 하단 `전투 / 기체 / 회수 / 도전 / 길드` 탭 구조
5. 현재 스테이지 카드 + 큰 `출격` CTA
6. 다음 신규 해금 미리보기
7. 출격 편성 화면
8. 액티브 후보 덱 8칸 UI
9. 지원 후보 덱 8칸 UI
10. 전투 진입
11. 결과 화면
12. 다음 스테이지/격납고 복귀

첫 테스트에서는 회수/도전/길드의 실제 서버 기능은 필요 없지만, 미구현 개발자 문구를 노출하지 않는다. 잠금 조건이 있는 최종 UI 구조만 사용한다.

## 첫 사용자 테스트 게이트

다음 조건을 모두 만족한 뒤에만 사용자에게 `테스트해 달라`고 요청한다.

- [ ] Unity 6000.3.19f1 import/compile 오류 0
- [ ] 홈 → 편성 → 전투 → 결과 → 홈 흐름 연결
- [ ] 메인 화면이 실제 모바일 라이브서비스 게임의 구색을 갖춤
- [ ] 중앙 기체/상단 재화/하단 탭/출격 CTA 가독성 확보
- [ ] 액티브/지원 덱 UI가 확장 가능하게 보임
- [ ] 이동/자동조준/3종 공격/3택 정상 동작
- [ ] 엘리트/보스 패턴 식별 가능
- [ ] 5분 전투 완주 가능
- [ ] Console error 0
- [ ] 플레이어 화면 개발자 문구 0

이후 Android 빌드와 실기기 테스트로 이동한다.
