# Stackfall Mobile 플레이어 노출 문구 규칙

이 문서는 실제 게임 화면에 들어가는 모든 텍스트의 절대 규칙이다.

## 1. 원칙

플레이어는 완성된 게임 세계와 서비스 정보만 본다.

개발 과정, 구현 상태, 내부 판단, 디버그 정보, 작업 메모는 게임 안에 노출하지 않는다.

## 2. 게임 안에서 금지하는 표현

다음 내용은 UI, 툴팁, 아이템 설명, 우편, 팝업, 채팅 시스템 메시지, 로딩 화면, 오류창, 상점, 이벤트 화면, 설정 화면에 넣지 않는다.

- 개발 중 / 미구현 / 임시 / 테스트 / 디버그 / WIP / TODO / placeholder
- 현재 구현 상태 / 개발 진척도 / 다음 개발 예정 / 추후 구현 예정
- 내부 코드명, 클래스명, 변수명, 서버 엔드포인트, 스택트레이스
- `V0`, `프로토타입 수치`, `밸런스 테스트용` 같은 개발 표식
- 다른 게임을 참고했다는 설명
- 개발자에게만 의미 있는 설계 이유나 주관적 메모
- 플레이어에게 필요하지 않은 기술 설명

## 3. 아직 열지 않는 기능

아직 제공하지 않는 기능은 메인 UI에 빈 버튼을 두고 `준비 중`, `개발 중`이라고 표시하지 않는다.

서비스상 의도된 사전 공개 이벤트나 시즌 예고가 아니라면 실제 사용 가능해지는 시점에 메뉴를 노출한다.

## 4. 오류 문구

오류 메시지는 내부 실패 원인이 아니라 플레이어 행동을 중심으로 작성한다.

예:

- 나쁜 예: `InventoryService validation failed: code 142`
- 좋은 예: `보상을 확인하지 못했습니다. 네트워크 연결을 확인한 뒤 다시 시도해 주세요.`

서버 추적용 오류 ID가 필요하면 사용자에게 의미 없는 기술 세부정보 대신 짧은 문의 코드 형태로만 표시할 수 있다.

## 5. QA/개발 UI

QA용 치트, 디버그 HUD, FPS/메모리 패널, 테스트 상점, 개발자 콘솔은 릴리스 콘텐츠와 분리한다.

- 개발/QA 빌드에서만 활성화
- 릴리스 빌드에서 코드 경로와 UI 리소스를 제외하거나 확실하게 비활성화
- 숨겨진 터치 영역만으로 보안을 대신하지 않음

## 6. 허용되는 운영 정보

다음은 실제 사용자에게 필요한 제품 정보이므로 허용한다.

- 앱 버전 번호
- 서비스 점검/장애 안내
- 실제 업데이트 내용
- 확률/천장/상품/결제 관련 법적 고지
- 개인정보/이용약관
- 고객지원 문의 코드

단, 이 경우에도 내부 개발 현황을 설명하는 문체를 사용하지 않는다.

## 7. 검수

출시 후보 빌드에서는 로컬라이제이션 전체 문자열을 검색하여 다음 계열 문자열을 확인한다.

`TODO`, `WIP`, `DEBUG`, `TEST`, `TEMP`, `PLACEHOLDER`, `미구현`, `개발 중`, `테스트용`, `임시`

정상 게임 세계관 문구 등 의도된 예외가 아니라면 릴리스 전 제거한다.
